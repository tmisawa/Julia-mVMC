CUDA backend: Linux RTX 3060 measurements (2026-10-12)

Scope and environment

These are warmed, fixed-configuration kernel/workload measurements, not complete optimization/PhysCal speedups. GPU0 ran correctness/debugging; GPU1 ran these benchmarks, with no second compute job on GPU1. CPU comparisons evaluate identical configurations, Hamiltonian/Green quantities and analytic parameter derivatives. Setup, parameter initialization, compilation and model uploads are excluded. Five synchronized repetitions report min/median/max; tables use wall-time medians. CUDA-event medians are also preserved in the accompanying text results.

Linux x8664, Ubuntu kernel6.8.0-146-generic; Intel Xeon E5-2699v3@2.30GHz; NVIDIA GeForce RTX3060 (12GiB, sm86); Julia1.13.1; CUDA.jl/CUDACore6.4.2; GPUArrays11.5.16; GPUCompiler2.13.4; LLVM20.1.8; CUDA runtime13.4.0 and compiler 13.4.92 (artifacts); NVIDIA driver580.178.04; forward-compatible driver artifact for CUDA13.3; cuBLAS13.8.0; cuSOLVER12.3.4; cuRAND10.4.4; CUPTI2026.3.1. Native CPU compiler: GCC/GFortran 13.3.0 (Ubuntu 24.04 packages). CPU BLAS: OpenBLAS ILP64 (`libopenblas64.so`), one thread. Production proposal words: cuRAND XORWOW, seed79. Walker kernels use32 threads/block and walker-first workspaces; Slater/cofactor contractions use double-precision cuBLAS.

Reference CPU source is upstream Julia-mVMC62416e30a04e33a6d3641351fa8487dd640473cb, with PfaPack9161cda40d6f69370b4104db865805de947686d9 and SFMT1526553009f318ae78338151460fda78beadddc2. CPU and GPU dependencies are pinned in test/gpu/Manifest-v1.13.toml. No historical fixtures were regenerated.

Residency verification

The warmed CUPTI region includes CUDA-generated proposal words,20 attempted proposals per walker, energy/Green calculations, analytic cofactor sensitivities and their GEMM contraction. All three runs recorded zero memory-copy records in that application region. The profiler's own dummy Int64 upload before its first synchronization is excluded using its documented display boundaries. Matrix GEMM alpha/beta scalars are resident; generic CUDA mul! would upload scalar references on every call.

Optimization boundaries still read solver status, maximum variance, energy and O(NPara) parameters for CPU C-compatible gauge shifts/rescaling. PhysCal copies its summary once. Callbacks may explicitly copy additional data. These transfers are not hidden by the inner-region measurement.

Correctness gates

GPU0:2022 assertions passed, including real/complex batched Pfaffians, sparse closed-form skew matrices, projected wavefunctions, CPU energies/Greens/analytic SR derivatives/updates, every proposal and decision on20-step shared UInt32 tapes, future-word and configuration repeatability on20-step production runs, input rejection, all5259 ordinary one/two-body operator quantities on8 configurations, and exact cofactor derivatives for a synthetic nodal QP sector.

Hubbard/Heisenberg SR comparisons measured derivative differences below2.7e-14, observable differences below1.2e-13, stabilized-system condition numbers2.30e3 and5.33e6, update differences2.32e-15 and2.02e-11, and solver residuals below1.2e-16. Update comparisons use explicit1e-9 absolute/relative tolerance plus a residual gate. Synthetic sparse/nodal mathematical checks are distinguished from CPU full-normal-factorization parity; no floating-point bitwise comparisons are used.

CPU-only gates on Julia1.13.1 passed: MVMCOptimizers unit suite (45349 assertions in its main unit group), full integration runner (including C-reference Lanczos and PairHop), PhysCal C references (31), and C ctest-equivalent gates (66). Native macOS GPU execution is unsupported; CPU portability is covered by upstream Linux/macOS CI. This report records local Linux results only.

L128 GPU speedup target: RTX3060 measurements

Measured scope

The target was20× versus single-thread Julia CPU. The verified two-device result is 13.98×, so the20× target remains unfulfilled (issue#81 stays open). These measurements evaluate identical fixed configurations, energy,256 one-body and768 direct two-body Greens, and772 analytic parameter derivatives. They do not measure complete optimization/PhysCal runs, compilation, input/model construction, initialization, thermalization, SR updates, or final output copies.

The single-device case uses configurations after12 one-proposal sampling calls; the two-device case uses the initial fixed batch. Adopted changes and transfers

The real Pfaffian assigns columns to warps, preserves pivot/product order, and uses explicit round-to-nearest multiply/add/divide operations. Slater updates use C's four spin-block expressions directly, with resident parameter indices, signs and rotation coefficients. Large inverse batches use cached device pointer tables for cuBLAS LU/inversion and enforce skew symmetry before use.

Only unoccupied Slater columns need batched GEMM; occupied columns satisfy A^-1*S_occ=-I. Ordinary operators evaluate independently against read-only virtual moves, followed by Hamiltonian addition in original input order. Large analytic derivatives use resident CSC coefficients and predecoded row coordinates, directly contracting inverse cofactors. Singular projection sectors retain exact minor evaluation with disjoint fallback workspaces.

The single-device warmed sampling+observable+derivative CUPTI application range records zero memory-copy records, including device-to-device copies. Profiler bookkeeping before its initial synchronization is excluded using the same range as CUDA's display. Two-device results are copied only after timing; their worker protocol does not transfer configurations or intermediate results between GPUs. Setup still constructs and uploads the dense Slater basis, so startup cost and memory capacity remain relevant. Each production optimizer/PhysCal runner uses one device; the two-device script shards only the fixed measurement workload.

The two-device large absolute errors occur with very large quantities, including an energy of approximately-1.43549e7; every relative/absolute elementwise gate passes, with zero mismatched observables and derivatives. Results are compared numerically, not bitwise.

A failing prototype exposed configuration29's projected-sum cancellation number sum(abs(weight*Pf))/abs(sum(weight*Pf))=2.521717e6, with individual matrix conditions85.6–3996.5. Basis GEMV first differed from CPU Slater elements by 4.44e-16. Separately, on identical CPU matrix inputs, implicit GPU multiply/add contraction changed per-sector Pfaffians by up to2.19e-13 relatively and the projected overlap by1.67854e-8. Direct Slater assembly and explicitly rounded Pfaffian/weight operations remove these divergences in this Linux case; the existing1e-9 projected gate passes. Neither seeds nor numerical thresholds were changed. The regression preserves that strongly cancelling configuration.

The final GPU suite passed 3957 assertions on GPU0. CPU-only verification and Linux/macOS CI from the initial GPU PR remain recorded in the earlier report. The follow-up GPU suite additionally checks64/128-site shared20-step trajectories, exact future UInt32 words/configurations, batched inverse residuals/singular flags, occupied/unoccupied transforms, all ordinary operator coincidences and singular-sector fused derivatives. Tiny raw parameters use independent C four-block closed forms, distinguished from historical Julia orbital-value filtering.
